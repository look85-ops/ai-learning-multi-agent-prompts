# AI Learning Multi-Agent Prompts

Пять ролей для последовательного проектирования одной образовательной задачи.

Это не набор «пяти чатов ради пяти чатов». Каждая роль уменьшает свой тип ошибки, возвращает структурированный результат и передаёт его следующему этапу.

## Когда использовать

Подходит, если нужно:

- превратить размытый запрос бизнеса в учебную задачу;
- спроектировать занятие с практикой и переносом в работу;
- собрать сценарий, которым сможет пользоваться преподаватель;
- провести независимую методическую и этическую критику;
- не выпускать AI-результат без доказательств и решения человека.

Для маленькой правки одного текста пять ролей избыточны. Для сложной задачи они полезны как разделение ответственности.

## Схема работы

```text
brief -> learning_spec -> draft -> critique -> evaluated_result
```

1. **Task Analyst** превращает запрос в brief: аудитория, контекст, ограничения и признаки успеха.
2. **Learning Designer** строит логику: цель, практика, обратная связь и перенос.
3. **Scenario Writer** превращает learning spec в рабочий сценарий занятия.
4. **Critic** ищет методические, фактические, реализуемые и этические слабые места.
5. **Eval Owner** проверяет результат по критериям и решает, что передать человеку.

## Быстрый старт

1. Скачай или открой пять файлов в порядке номеров.
2. Возьми синтетическую задачу. Например: «Спроектировать 45-минутное занятие для новых руководителей о развивающей обратной связи».
3. Передай исходный запрос `01-task-analyst.md`.
4. Передай его результат `02-learning-designer.md`, затем двигайся по цепочке.
5. Не пересказывай результат вручную: передавай следующий агентский вход целиком, включая ограничения и открытые вопросы.
6. Покажи человеку `evaluated_result`, а не только финальный текст.

## Контракт передачи

Каждый этап должен содержать:

- результат текущей роли;
- ограничения, которые нельзя потерять;
- открытые вопросы;
- критерии приёмки следующего этапа.

Если роль меняет цель или логику, она должна явно написать об этом в блоке `На проверку`, а не исправлять молча.

## Что получает человек на выходе

- один сценарий занятия;
- карту рисков и найденных слабых мест;
- таблицу `PASS / FAIL / REVIEW`;
- список решений, которые должен принять специалист;
- одно следующее действие с владельцем и критерием готовности.

## Ограничения

- Пять ролей не гарантируют качество сами по себе.
- Критик не должен превращаться в генератор вкусовщины.
- Eval Owner не имеет права ставить `PASS` без доказательства.
- Не передавай в промпты персональные данные и закрытые документы.
- Сравнивай мультиагентный прогон с более простым baseline, если хочешь доказать пользу архитектуры.

## Файлы

- `01-task-analyst.md` — постановка задачи;
- `02-learning-designer.md` — учебная логика;
- `03-scenario-writer.md` — сценарий занятия;
- `04-critic.md` — независимая критика;
